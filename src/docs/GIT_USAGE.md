# Git 使用说明
此文档用于说明项目中 Git 的使用方法和规范。

## 安装与使用
### 第一步：准备工作
1. **Watt Toolkit**：安装 Watt Toolkit 用于加速 Github。
    - [Watt Toolkit 下载链接](https://steampp.net/download)
2. **VSCode**：安装 VSCode 用于代码编辑与可视化提交。
    - [VSCode 下载链接](https://code.visualstudio.com/)
3. **Godot**：下载 Godot 引擎。
    - [Godot 下载链接](https://godotengine.org/download)
    - 由于项目使用的是 GDScript 语言，所以需要下载普通版本的 Godot，而不是 .NET 版本。
4. **Git**：安装 Git 用于版本控制。
    - [Git 下载链接](https://git-scm.com/downloads)
    - 注：若看不懂安装程序，只需要点下一步即可。
5. **Github**：注册 Github 账号。
    - [Github 链接](https://github.com)
    - 注：如果无法访问 Github，请先打开 Watt Toolkit 加速 Github。

### 第二步：配置 Git 环境
1. 首先在开始菜单中打开 Git Bash。
2. 最后输入以下命令配置 Git 用户信息（回车确认）：
    ```git
    git config --global user.name "你的姓名"
    git config --global user.email "你的邮箱"
    ```
    示例：
    ```git
    git config --global user.name "张三"
    git config --global user.email "1729000000@qq.com"
    ```

### 第三步：克隆项目仓库
1. 首先打开 VSCode。
2. 点击欢迎页面的 “克隆 Git 仓库” 按钮。
3. 登录 Github 账号。
4. 点击从 Github 克隆并输入 https://github.com/fepeng114514/FreeRadical.git。
5. 最后选择克隆到的目录即可。

注：若无法访问服务端，请先打开 Watt Toolkit 加速 Github。

### 第四步：使用 Godot 打开项目并修改代码
修改前，需要先拉取最新代码，避免修改时出现冲突。

1. 首先打开 VSCode。
2. 点击打开文件夹，选择项目目录。
3. 点击左侧 “源代码管理” 选项。
4. 点击图形栏的 “拉取” 按钮，拉取最新代码。
5. 打开 Godot，选择项目目录。
    - 首次打开时 Godot 可能会未响应，请耐心等待项目加载完成。
6. 最后修改代码即可。

### 第五步：提交代码到仓库
1. 首先点击 “源代码管理” 选项。
2. 输入提交信息。
    - 提交规范见下方。
3. 点击 “提交” 按钮。
4. 暂存所有修改。
5. 最后点击 “同步更改” 按钮。

注：若无法访问服务端，请先打开 Watt Toolkit 加速 Github。

#### 冲突解决
提交时若出现冲突，需要先解决冲突，再提交。

1. 点击冲突的文件。
2. 根据冲突提示，选择解决冲突的方式。
    - 可以选择应用本地修改、应用远程修改或合并修改。

##### 示例
你修改了哥布林的血量为 100，但别人修改了哥布林的血量为 150，物理护甲为 10。

此时提交时会提示冲突，需要先解决冲突，选择应用本地修改或应用远程修改，再提交。

- **应用本地修改**：
    - 应用你自己的修改，血量为 100。
- **应用远程修改**：
    - 应用别人的修改，血量为 150，物理护甲为 10。
- **合并修改**：
    - 血量需要自行选择本地或远程，物理护甲为 10。

#### 提交规范
本项目使用约定式提交规范。核心格式如下：

```
<类型>[可选范围]: <描述>

[可选的正文]
```

##### 规范
1. 末尾增加句号。
2. 所有英文与中文之间用空格隔开。

##### 常用类型
1. **feat**: 新增功能。
2. **fix**: 修复 Bug。
3. **docs**: 仅文档变更。
4. **style**: 代码格式（不影响逻辑，如空格、缩进）。
5. **refactor**: 代码重构（不修 Bug 也不加功能）。
6. **perf**: 性能优化。
7. **test**: 添加或修正测试。
8. **chore**: 构建流程、工具等变动。
9. **ci**: CI 配置或脚本修改。
10. **build**: 影响构建系统或外部依赖。
11. **revert**: 回滚到之前的版本。
12. **balance**: 游戏平衡性调整。

##### 示例
###### 示例 1：
feat(登录): 增加手机号验证码登录方式。

- 新增验证码发送接口。
- 增加登录校验逻辑。

###### 示例 2：
fix: 修复用户未登录时页面白屏的问题。
